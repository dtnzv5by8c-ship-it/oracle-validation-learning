## 2. Correction: FootyStats `no_home_away` semantics

A previous reconciliation note stated that the public documentation did not define `no_home_away`. That statement is superseded.

The current official FootyStats documentation explicitly defines the field:
- Match Details: `no_home_away` is set to 1 if there is no home or away distinction for the match.
- League Matches: the same definition is published.

This is a match-level orientation flag. Do not reinterpret it as merely a neutral-venue indicator, and do not treat home/away orientation as valid for a row where the flag is 1 without an explicit approved handling rule.

The prior 31 October runtime/snapshot reconciliation recorded 66 runtime rows with `no_home_away=1`. Those rows therefore require a visible report-level orientation warning. This does not authorise changing Oracle V1.6 outputs or probabilities.

Code inspection found no `no_home_away` handling in `scripts/build_selected50_market_intelligence_report.py`. The repair workflow consumes the runtime prediction CSV and schedule-coverage CSV; it does not currently download or pass the current fixture snapshot as an input. Consequently, the existing workbook rebuild cannot independently surface this snapshot flag without a report-only snapshot overlay/input being added.
