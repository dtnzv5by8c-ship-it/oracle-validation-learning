# Project Oracle Lessons Learned

Last updated: 2026-11-27

## Permanent operating rule — historical-first, never restart from scratch
Before diagnosing or changing anything, inspect the live public GitHub state, active workflow runs, `docs/PROJECT_ORACLE_LESSONS_LEARNED.md`, `docs/PROJECT_ORACLE_CONTINUATION_STATE.md`, the latest QA/root-cause artifacts, and the most recent relevant commits. Reuse proven fixes and regression controls first. Never rediscover a previously solved defect as if it were new. Every newly confirmed root cause must be recorded here with evidence, fix commit, validation result, and a regression guard.

## 2026-11-27 — recurring current-data validation contract defect
- The rolling 50-league universe means **50 governed leagues**, not necessarily 50 distinct `league_season_id` values in every rolling fixture window. A current window can legitimately contain fixtures from fewer than 50 league-season IDs.
- A Team State gate incorrectly required exactly 50 distinct `league_season_id` values in the fixture spine. The authoritative manifest already declared `governed_leagues=50` and `season_ids_with_fixtures=41` for the 27 Nov–4 Dec window.
- Permanent fix: validate `manifest.governed_leagues == 50` and require at least one fixture-bearing season ID; do not equate current fixture-bearing season count with governed universe size.
- Fix commit in `oracle-football-data`: `2b56ee95f9ade3f4c2307e46b4b14e929670432a`.
- Regression requirement: retain this semantic distinction in all future 50-league gates and reject any new check that interprets fixture-window season count as governed-league count.

## 2026-11-27 — timestamp drift contract defect
- Current-source and rolling-spine manifest timestamps are generated by different process stages and are not expected to be identical.
- Permanent fix: reconcile the exact rolling-spine SHA-256 and exact Fixture-ID-set SHA-256 instead of comparing independent generation timestamps.
- Fix commit in public workflow: `21d848db17ac1f05dbe71c02fe358f172686a28`.
- Regression requirement: identity/hash equality is authoritative; independent process timestamps are diagnostic only.

## 2026-11-27 — current prediction ledger dependency
- The Master OMI chain requires an authoritative current prediction ledger before the workbook can be certified.
- Permanent workflow control: build `research/four_model/outputs/omi_prediction_ledger_current.csv` directly from the governed rolling fixture spine, enforce row parity and exact Fixture-ID set equality, then persist it before downstream OMI certification.
- Do not treat a green upstream workflow as sufficient if the ledger is absent.

## Historical recurring fixes that remain binding
- Current Team State must use exact provider IDs and strict pre-kickoff chronology; no name-based admission, fuzzy matching, aliases, stale fallback, or cross-provider identity bridge.
- Genuine no-history H2H is a reporting-quality classification, not a fabricated zero; it must remain explicitly unavailable where evidence does not exist.
- Current Team State persistence must be validated at byte/blob level: non-empty CSV, manifest row-count parity, staged blob size/hash parity, and remote blob parity after push.
- Only the dedicated current-data lane may publish the durable current Team State source of truth; analytical/OOS lanes must not race to publish the same artifact.
- Shots/SOT must propagate from upstream evidence into Team State; never hard-code them missing when source evidence exists.
- A:ET is immutable; post-ET intelligence is append-only; Oracle V1.6 production logic is unchanged.
- No estimation, zero-fill, stale/historical substitution, timezone normalization, post-kickoff leakage, unsupported provider substitution, or fuzzy fixture matching.
- Production remains fail-closed until independent 100% QA certifies the canonical workbook.

## Current control lessons
- GitHub live state is authoritative; never assume a file or workflow exists because it was mentioned in prior conversation context.
- Inspect live HEAD and active workflow runs before changing or rerunning anything.
- A failed downstream quality step caused by a skipped upstream artifact must be classified separately from the upstream root cause.
- H2H team aliases are reporting-only identity controls; they must never rewrite canonical Fixture IDs or competition identity.
- Genuine no-history H2H, unresolved team identity, and league-code conflict must remain separate fail-closed classifications.
- Never weaken quality gates to obtain a green workflow.
- Challenger prediction/settlement evidence cannot be promoted to Oracle V1.6 production evidence.
- Missing settlement provenance must remain incomplete; never infer source fields from outcome data.
- Exhausted provider experiments remain quarantined unless new evidence changes the entitlement/root-cause assessment.
- A running equivalent workflow is not duplicated.

## Production readiness
Production remains fail-closed until canonical 50-league source/identity, snapshot, xG, odds, freshness, market observation, prediction linkage, workbook schema/type integrity and verified settlement gates pass.
